# Reviewed public source export

The canonical development checkout remains authoritative. A public source snapshot is generated from its current reviewed files without copying Git metadata or private history. Subsequent application changes must be made in the canonical source and re-exported; generated packaging adaptations are recorded per file.

The export includes application and worker source, workspace packages, migrations, tests, scripts, infrastructure examples, root configuration, lockfile, reviewed current documentation, and the approved CPL product mark. Customer-supplied original documents/logos, historical documentation and verification reports, private handoffs, local environments, databases, credentials, logs, dependency/build trees, and Git metadata are excluded. Synthetic legacy test fixtures remain explicitly synthetic. No source license is added.

The Windows publication checkout is `D:/Cyber Pirate Labs/93_TOOLS_AND_CACHE/CPL-Command-Center/publication/source`; its independently fetched verification clone is the sibling `anonymous-clone`. Linux verification paths are exactly `/workspace/CPL-Command-Center-Public` and `/workspaces/CPL-Command-Center-Public`. The public guard requires the new repository identity marker and the exact `AaronStarrett/CPL-Command-Center-Public` origin. These constraints intentionally fail closed for other checkout locations.

From the canonical checkout, `node scripts/publication-export.mjs --plan <absolute-SSD-review.json> --repository-id <public-repository-id>` writes a redacted review manifest. Inspect its paths, adaptation list, source hashes, privacy/secret results, and dependency notice inventory. `node scripts/publication-export.mjs --export --review <same-review.json> --repository-id <same-id>` recomputes the complete plan and refuses changed inputs. The initial destination must be empty. `--refresh` permits updating a previously generated candidate only when its existing exported files still match its manifest; it never deletes files or overwrites independently changed source. No Git or remote publication mutation is performed by this script.

Publication scanning checks secret patterns, preserved private profile phrases, literal OS account profile paths, and concrete local visualization session paths. The account identity comes from the operating system rather than redirected verification environment variables. Findings expose only the export file path and category; the private matching context stays in process memory. Generated publication metadata receives the same content checks.

`node scripts/publication-export.mjs --verify <allowed-public-checkout>` verifies the exact exported file hashes and rejects unexpected source files. Installed dependencies, Git metadata, and ignored build/test outputs are excluded from that comparison. Final secret scanning, clean installation, application tests, build/browser checks, remote cost-control checks, and anonymous GitHub readback remain separate release gates. A manifest is not a production-readiness claim or a substitute for human confidentiality and rights review.

Packaging adaptations are limited to the public repository identity and guard roots, public asset-integrity verification, public README/agent instructions, generated file inventory, and deterministic line endings matching `.gitattributes`. Text is exported with LF, except Windows `.cmd` wrappers use CRLF; Git index comparisons account for Git's LF text storage. Canonical tests explicitly validate their current private or public repository identity and history; their assertions are not rewritten by the exporter. Application source, tests, migrations, and lockfile retain their canonical content after sanitation; any line-ending adaptation and the original source SHA256 are recorded. Approved binary assets remain byte-for-byte unchanged. Parked workflow source is retained for its cost-control regression tests; it has no automatic trigger and every job is disabled.
